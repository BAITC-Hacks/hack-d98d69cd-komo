## Порядок работы после получения ТЗ

1. Сохранить задание и источник официальной публикации. Разобрать: **требование → критерий оценки → реализация → способ проверки**.
2. Проверить обязательные технологии, данные, формат сдачи, репозиторий организатора, модели, лимиты и срок действия доступов.
3. Выбрать минимальный стек и основной сценарий. Зафиксировать вход, результат, действия агента и критерий успеха.
4. Создать полный путь от входной задачи до результата, затем закрыть остальные обязательные требования.
5. Проверить основной сценарий с реальной моделью, фактические эффекты инструментов, некорректный ввод, ошибки API и нехватку данных. Заглушки обозначать явно.
6. Проверить чистый запуск по README без неописанных локальных файлов, личных сессий и подписок.
7. После разрешения пользователя на коммиты вести почасовую фиксацию и отправку изменений; завершить сдачу до дедлайна и записать итоговый SHA и подтверждение приема.

Итоговый README должен содержать назначение, архитектуру, технологии, системные требования, зависимости, параметры окружения, установку, запуск, демонстрационные доступы и проверку основного сценария. Точные команды писать и подтверждать по реальному приложению.

Технические проверки, build, работа интерфейса, вызов модели и выполнение внешнего действия — разные виды доказательств. Нельзя называть интеграцию проверенной по одному успешному build или демонстрационной заглушке.

## Цель и оценка

По п. 2.1 участники за пять часов создают технологические решения с использованием современных инструментов разработки и ИИ. Лендинг позиционирует мероприятие как agentic-AI хакатон. Точные функции агента и обязательные технологии определит конкретное ТЗ.

Наш ориентир: реальный пользовательский сценарий, проверяемый результат и воспроизводимый запуск. Общая концепция агента для обсуждения: получить задачу, выбрать необходимые инструменты, выполнить действия, проверить результат и объяснить его пользователю. Конкретная автономность определяется ТЗ.

Технический отбор проходит по требованиям, правилам начисления баллов и критериям выбранной задачи, опубликованным до старта (п. 5.5). Баллы Demo Day не подменяют технические критерии.

| Ориентир Demo Day | Баллы |
| --- | ---: |
| Ценность решения | 25 |
| Результат и качество решения | 20 |

Это ориентирующая шкала. Коллективное решение жюри имеет приоритет над предварительным арифметическим рейтингом (п. 5.7). AI-судья может быть вспомогательным инструментом; его роль определяет организатор (раздел 4).

## Варианты реализации

| Вариант | Когда выбирать | Что потребуется для воспроизводимой сдачи |
| --- | --- | --- |
| [n8n](https://docs.n8n.io/build/build-and-manage-agents.md) | Основная работа — интеграции и цепочки действий: обращения, таблицы, документы, HTTP API | Версия среды, экспорты workflow, схема подключения credentials, данные и проверка импорта |
| [OpenAI API и собственный код](https://developers.openai.com/api/docs/guides/tools) | Нужна собственная логика, интерфейс и небольшой набор инструментов | Код, зависимости, конфигурация модели, инструкция запуска и реальные проверочные сценарии |
| [OpenAI Agents SDK](https://developers.openai.com/api/docs/libraries#use-the-agents-sdk) | Нужны управление выполнением агента, инструменты и трассировка в Python или TypeScript | Код агента и инструментов, конфигурация, зависимости и доказательства выполнения |
| [LangGraph](https://docs.langchain.com/oss/python/langgraph/overview) | Требуются сложные переходы, сохранение состояния и продолжение выполнения | Определение графа, способ хранения состояния и проверки переходов и восстановления |
| [Dify](https://docs.dify.ai/en/cloud/use-dify/getting-started/introduction) | Задача строится вокруг документов, базы знаний, диалога и визуального сценария | Экспорт приложения, исходные данные, настройки провайдеров, версия и проверка восстановления |

У этих инструментов разные роли: OpenAI API дает доступ к моделям, а n8n, SDK, LangGraph или Dify организуют выполнение сценария. Наличие доступа к модели само по себе не создает готового агента.

По умолчанию начинать с одного агента и минимального достаточного числа компонентов. Не добавлять одновременно несколько платформ оркестрации без конкретной потребности. Модель, язык, интерфейс и хранилище выбрать по требованиям задачи и доступам.

## n8n и Dify: переносимость

- n8n сохраняет workflow в JSON и поддерживает экспорт и импорт. Сохранять актуальный экспорт в официальном репозитории при фиксации изменений. Проверить, что восстановлены все связанные сценарии и необходимые данные. [Экспорт n8n](https://docs.n8n.io/build/manage-workflows/export-and-import.md).
- Экспорт n8n может содержать имена credentials и встроенные заголовки авторизации в HTTP-узлах. До коммита проверить содержимое; сами учетные данные настроить отдельно.
- Dify экспортирует настройки приложения, промпты и связи с базой знаний, но не саму базу знаний и не ключи сторонних инструментов. Для восстановления нужны исходные данные и инструкция их загрузки. Не включать секретные переменные в экспорт. [Экспорт Dify](https://docs.dify.ai/en/cloud/use-dify/workspace/app-management).
- Облачная ссылка не заменяет материалы для самостоятельного запуска. До выбора платформы проверить ее доступность экспертам, условия лицензии и время развертывания.

## OpenAI и NVIDIA

По информации пользователя организаторы предоставят API OpenAI и ресурсы NVIDIA. Пока не получены и не проверены:

- доступные модели, API endpoint и способ авторизации;
- поддержка вызова инструментов, формата результата и нужных типов входных данных;
- квота, ограничения частоты запросов, параллельность и срок действия доступа;
- возможность независимой проверки экспертами 24–28 сентября и на Demo Day 29 сентября;
- формат NVIDIA: готовый API, вычислительный сервер или иной сервис.

Если будет выдан NVIDIA NIM, его API может использовать совместимые с OpenAI интерфейсы; конкретные возможности зависят от выданной версии, модели и endpoint. Не считать наличие полного API OpenAI или GPU-сервера подтвержденным. [Пример документации NIM 2.0.1](https://docs.nvidia.com/nim/large-language-models/2.0.1/reference/api-reference.html).

После выдачи доступов проверить небольшой реальный запрос и необходимый вызов инструмента. Ключи не отправлять в чат и не коммитить; использовать локальное окружение. Расходующие квоту тесты в ходе этой подготовки не выполнялись.

# Career Quest · KOMO

AI-навигатор развития сотрудника для HackAlem AI, кейс Halyk Bank. Модульный монолит: **FastAPI + PostgreSQL + Redis**, интерфейс **Next.js + TypeScript**.

Сотрудник видит цель, навыки и историю, получает 1–3 обоснованных шага, подтверждает выполнение и видит изменение прогресса. HR видит дефициты компетенций, участие и сотрудников без актуального шага, загружает дополнительные профили и историю.

## Быстрый запуск

Нужны Docker Engine / Docker Desktop и Docker Compose 2.24+ с поддержкой `env_file.required`. Первая сборка скачивает образы и зависимости; основные экраны работают локально, AI требует внешнего доступа. Страница Swagger загружает UI-ресурсы с CDN; JSON-схема API доступна локально. Проверенное окружение: Docker 28.5.1, Compose 2.40.3.

Из корня репозитория:

```sh
docker compose up --build
```

Открыть **http://localhost:3000**. Миграции, исходные данные и демо-аккаунты создаются автоматически. PostgreSQL/Redis не публикуют порты; web привязан к localhost.

| Роль | Логин | Пароль по умолчанию |
| --- | --- | --- |
| Сотрудник | `employee` | `employee-demo-2026` |
| HR | `hr` | `hr-demo-2026` |

Это публичные демонстрационные учетные данные для синтетического локального приложения. Сотрудник привязан к **E0028**, у которого изначально доступен самостоятельный курс Cloud Certification Prep. Пароли и привязка меняются через конфигурацию.

Обычный `docker compose down` сохраняет volume БД. Повторный запуск не сбрасывает импорт и историю выполнения. Не используйте `down -v` для рабочего проекта, если хотите сохранить данные.

## Реальный AI и конфигурация

В локальном `.env` задайте действующий ключ OpenAI Platform. Подписка ChatGPT не заменяет API-доступ. Если файла нет, используйте `.env.example` как образец. **Существующий `.env` не перезаписывайте.**

| Переменная | Назначение / значение по умолчанию |
| --- | --- |
| `OPENAI_API_KEY` | Основное имя API-ключа |
| `OPENAI_KEY` | Альтернативное имя; основное имеет приоритет |
| `OPENAI_MODEL` | `gpt-4.1-mini-2025-04-14` |
| `EMPLOYEE_ID` | `E0028`, профиль демо-сотрудника |
| `EMPLOYEE_PASSWORD`, `HR_PASSWORD` | Пароли демо-аккаунтов, применяются при seed |
| `SESSION_SECRET` | Подпись cookie; если отсутствует, генерируется один раз в БД |
| `WEB_PORT` | `3000` |
| `APP_ORIGIN` | `http://localhost:3000`, должен соответствовать порту web |

После смены ключа пересоздайте API:

```sh
docker compose up -d --force-recreate api
```

Ключ находится только в backend. В OpenAI отправляются синтетические роль/грейд/стаж/формат работы, цель, навыки, допустимые события и агрегаты истории. Имя, ID сотрудника, руководитель, ID участия и сырая история не отправляются. Используется `store=False`.

При отсутствии ключа, 401, таймауте или невалидном ответе включается явно обозначенный **резервный подбор**. Он не доказывает работу AI. Проверка реального подключения:

```sh
docker compose exec api python -m app.smoke_ai
```

Скрипт делает один запрос, проверяет `source=ai`, выводит только результат и задержку. Ключи не печатаются. Если ответ взят из кеша, это отмечается отдельно.

Для независимой проверки экспертам нужны отдельно предоставленные действующие демонстрационные API-доступы через разрешенный организатором канал. Личная подписка участника, требование «купить свой ключ» и один fallback не заменяют этот доступ. Ключи не передаются через Git.

## Демонстрация за 2–3 минуты

1. Войти как `employee`: показать цель Senior, прогресс и разрывы.
2. Нажать **«Подобрать с AI»**, проверить источник ответа, раскрыть **«Почему этот шаг»**: профиль, навыки, история, требования цели.
3. В **«Доступных активностях»** завершить Cloud Certification Prep. Показать изменение и обновить страницу — результат сохраняется.
4. Войти как `hr`: показать компетенции, статусы рекомендаций и участие по активностям.
5. В **«Импорте данных»** загрузить оба файла из `docs/fixtures/`, перейти к `CQ_CASE_01` и запустить подбор.

Повторное начисление за завершенный курс запрещено. Будущие сессии нельзя завершить раньше времени. Подтверждение пользователя не проверяет реальное прохождение внешнего курса. Для повторения демо с исходными данными используйте отдельный тестовый проект.

## Архитектура и фичи

`Browser → Next.js /api/v1 proxy → FastAPI → PostgreSQL / Redis / OpenAI Responses API`.

| Backend-фича | Ответственность |
| --- | --- |
| `identity` | Вход, подписанная HttpOnly cookie, серверные права |
| `catalog` | Навыки, требования ролей, события |
| `employees` | Исходные профили, чтение пользовательского состояния |
| `development` | Единые расчеты навыков, целей, допуска, прогресса, завершения |
| `recommendations` | AI-выбор, схемы, валидация, доказательства, fallback, кеш |
| `hr_analytics` | Агрегаты и причины отсутствия актуального шага |
| `data_import` | Шаблоны Excel/JSON, валидация и атомарная загрузка Excel/JSON/CSV |

Frontend разделен по фичам; страницы собирают их, `shared` содержит общий API-клиент и UI-компоненты. Формулы не дублируются на TypeScript. Сотрудник работает только со своим профилем; HR читает чужие профили, но не подтверждает выполнение за сотрудника.

API: **http://localhost:3000/api/v1/docs**. Снимок контрактов: `docs/openapi.json`; генерируемые TS-типы: `frontend/src/shared/api/schema.d.ts`.

## Правила расчета и допущения

- Исходный набор: 200 сотрудников, 40 событий, 60 навыков, 32 требования ролей/грейдов, 2743 участия. Файлы `career_quest_dataset/` не изменяются.
- Расчетное сегодня — **2026-10-01**. Системное время используется для cookie, кеша и длительности запросов.
- Базовые навыки соответствуют `last_review_date`. Учитываются последующие завершения; отсутствующий навык равен 0. Формула: `max(current, min(5, max_level, current + gain))`.
- Для self-paced истории нет даты завершения: дата строки используется как приближение. Импортированное завершение в день оценки считается уже учтенным. Новое подтверждение в приложении в этот же день считается совершенным после загруженной базовой оценки.
- Обязательные события не рекомендуются, но их фактический прирост учитывается, включая EV_004. Завершенные события не повторяются, кроме отдельных участий в EV_036.
- Явная цель может менять роль. Без цели выбирается следующий грейд текущей роли; для Lead — поддержание текущих требований. Это отображаемое MVP-допущение.
- Прогресс: сумма `min(current, required)` / сумма требований × 100. При пустых требованиях — 100%. Грейд автоматически не меняется.
- Допуски учитывают текущую роль/грейд, prerequisites, историю, расписание и полезный прирост. Если прямого шага нет, проверяется один подготовительный переход через prerequisite.
- Резервный подбор: критический прирост ×5, полезный прирост ×2, история участия и трудоемкость. AI выбирает среди всех допустимых кандидатов; код проверяет IDs, уникальность и минимум три фактора.
- Факты и числа формируются сервером. Непроверенный текст модели не показывается как факт. Для каждого шага прирост рассчитан отдельно относительно текущего состояния; эффекты нескольких рекомендаций не складываются.
- Выполнение и импорт используют короткую транзакционную блокировку состояния набора. Идемпотентность и ограничения БД защищают от двойного начисления.
- Ревизия общая: изменение данных делает прошлые рекомендации устаревшими. Это консервативное упрощение MVP. Redis кеширует успешный подбор на 5 минут; его отказ не блокирует работу.

## Импорт

На `/hr/import` выберите формат и нажмите **«Скачать шаблон»**: Excel (.xlsx) или JSON с синтетическим примером. Замените пример своими данными и загрузите в **«Профили сотрудников»**. Один файл может включать и профили, и историю — тогда второй файл не нужен.

- **Excel:** лист `employees` — полные профили, `employee_skills` — строки `employee_id, skill_id, level`, `history` — история. Листы `roles`, `skills`, `events` содержат справочники; `instructions` — инструкцию. Названия листов и колонок сохраняйте, порядок колонок можно менять. Пустые строки пропускаются. Даты — ячейки Excel или `YYYY-MM-DD`. Формулы перед загрузкой замените значениями. Старые `.xls` пересохраните как `.xlsx`.
- **JSON:** исходный `{meta, employees}`, массив профилей или общий `{meta, employees, history}`. При отсутствии `meta` применяется Career Quest 1.0, срез 2026-10-01. Для отдельной истории — массив записей или `{history: [...]}`.
- **История отдельно:** Excel с листом `history`, JSON или CSV в UTF-8. CSV принимает запятую или точку с запятой, порядок исходных колонок свободный. Можно совместить JSON профилей и Excel/JSON/CSV истории. Один вид данных нельзя передавать сразу в двух файлах.
- Для импорта только профилей удалите строки примера на `history` или сам лист. Для импорта только истории оставьте `history` и справочники. Пустой `employee_skills` означает отсутствие оценок. Профили заменяются целиком — это не частичное обновление отдельных полей.
- Лимиты: 4 МБ на файл, 2000 профилей / 20 000 участий за запрос; распакованный Excel до 32 МБ. Ошибки структуры Excel указывают лист, строку и поле, ошибки связей — ID профиля или участия. Новые ID поддерживаются.

API шаблона: `GET /api/v1/hr/import/template?format=xlsx|json`, только для HR. Шаблоны хранятся в `backend/app/features/data_import/templates` и входят в Docker-образ. OpenAPI и TypeScript-типы обновлены.

Проверяются значения, статусы, ссылки, роли/грейды, навыки и дата среза. Повторные ID внутри пакета отклоняются; идентичный повторный импорт не добавляет записи. Обновления атомарны. Подтвержденные в приложении выполнения нельзя молча перезаписать импортом; несовместимый срез отклоняется.

Три собственных синтетических примера в `docs/fixtures/` проверяют критический разрыв против минимального навыка, prerequisites/потолки и смену роли без истории. Это **не профили жюри**.

## Проверки

Интеграционные тесты изменяют БД. Используйте отдельный проект:

```sh
WEB_PORT=3001 APP_ORIGIN=http://localhost:3001 docker compose -p career-quest-check up -d --build
docker compose -p career-quest-check exec api python -m pytest -q
```

Backend-тесты подменяют только AI-провайдер явной фикстурой. PostgreSQL и Redis реальные. Эти тесты не доказывают вызов OpenAI.

Frontend, Node.js 22:

```sh
cd frontend
npm ci
npm run typecheck
npm run build
npx playwright install chromium
npm run test:e2e
```

Если Chromium не скачивается, но установлен Google Chrome, используйте `PLAYWRIGHT_CHANNEL=chrome npm run test:e2e`. Браузер запускается с отдельным временным профилем. `TEST_BASE_URL` по умолчанию — `http://localhost:3001`. Тест завершает демо-курс; для полного повторения с исходным состоянием удалите только временный проект и запустите его заново:

```sh
docker compose -p career-quest-check down -v
```

После изменения API пересохраните `docs/openapi.json` и выполните `npm run api:types`. Генерируемые типы вручную не правятся. Доказательства проверок — `docs/VERIFICATION.md`; скриншоты и отчеты создаются в игнорируемых `artifacts/`, `test-results/`.
